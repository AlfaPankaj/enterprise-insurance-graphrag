# How BM25 Fits Into Your lexical Backend
Rather than using a simple token-overlap heuristic (which unfairly penalizes short node texts and rewards repetitive word counts), implementing BM25 inside lexical gives you three major upgrades:

1. Length Normalization: Nodes containing full policy clauses won't artificially outrank concise claim summaries just because they happen to contain more total words.
2. Term Frequency Saturation: If a search query keyword appears 10 times in a single node, BM25 dampens the score so it doesn't overpower other relevant matches.
3. Hybrid Exact Match Boost: You can combine BM25 scoring with your planned entity-id-match rule.
```
Score = BM25(Q, NodeText) + EntityMatchBonus
```
If the query explicitly mentions a exact policy ID or claim number (e.g., CLM-88301), the EntityMatchBonus guarantees that node jumps to Rank 1, while BM25 ranks the remaining context nodes by term relevance.

## code (src/graphrag/reranker.py)
```python
# ---------------------------------------------------------------------------
# BM25 (Okapi) — pure-Python, zero dependencies
# ---------------------------------------------------------------------------

_K1 = 1.5   # term-frequency saturation
_B = 0.75   # length-normalization strength (Lucene defaults)
_ID_BONUS = 5.0  # entity-id match: guarantees an explicitly-named id ranks #1


def _bm25_idf(n_docs: int, df: int) -> float:
    """Robertson-Sparck Jones IDF with +1 smoothing (never negative)."""
    return math.log((n_docs - df + 0.5) / (df + 0.5) + 1.0)

def _prefix_variants(query_tok: str, vocab: set[str]) -> set[str]:
    """Exact term or shared-prefix (len >= 4) variants — covers singular/plural
    and morphological pairs (coverages/coverage, investigates/investigator)
    without a full stemmer."""
    if not vocab:
        return {query_tok}
    variants = {t for t in vocab if t == query_tok
                or (len(query_tok) >= 4 and len(t) >= 4
                    and (t.startswith(query_tok) or query_tok.startswith(t)))}
    return variants or {query_tok}
```
```python
# ---------------------------------------------------------------------------
# lexical backend (deterministic fallback)
# ---------------------------------------------------------------------------

class LexicalReranker:
    """Okapi BM25 over node texts, plus an entity-id match bonus.

        score = BM25(query, node_text) + 5.0 * (query names this entity id)

    BM25 provides length normalization (a verbose policy node cannot outrank a
    terse claim summary just for being longer) and term-frequency saturation
    (a keyword repeated 10x does not dominate the ranking). The entity-id
    bonus guarantees an explicitly-named policy/claim number jumps to rank 1,
    while BM25 orders the remaining context nodes by term relevance.
    """

    name = "lexical"

    def rank(self, query: str, nodes: list[dict]) -> list[tuple[dict, float]]:
        if not nodes:
            return []
        q_tokens = query_tokens(query)
        q_ids = set(re.findall(ENTITY_ID_RE, query.upper()))

        docs = [_TOKEN_RE.findall(_node_text(n).lower()) for n in nodes]
        n_docs = len(docs)
        avgdl = sum(len(d) for d in docs) / n_docs
        vocab = {t for d in docs for t in d}
        df = Counter(t for d in docs for t in set(d))
        variants = {qt: _prefix_variants(qt, vocab) for qt in q_tokens}

        scored: list[tuple[dict, float]] = []
        for node, tokens in zip(nodes, docs):
            tf = Counter(tokens)
            doc_len = len(tokens)
            score = 0.0
            for qt in q_tokens:
                idf = _bm25_idf(n_docs, df.get(qt, 0))
                # one contribution per query token: the strongest variant match
                # (max, not sum — "claim" + "claimant" is one piece of evidence)
                best = max((tf.get(t, 0) for t in variants[qt]), default=0)
                if not best:
                    continue
                denom = best + _K1 * (1 - _B + _B * (doc_len / avgdl))
                score += idf * (best * (_K1 + 1)) / denom
            id_bonus = _ID_BONUS if node["id"].upper() in q_ids else 0.0
            scored.append((node, score + id_bonus))
        scored.sort(key=lambda t: t[1], reverse=True)
        return scored
```
## Maths used BM25 

The Robertson-Spärck Jones IDF formula with the $+1.0$ floor calculation is mathematically sound, robust, and correctly configured for a graph retrieval system.Mathematical VerificationStandard Robertson-Spärck Jones IDF without smoothing produces negative scores when a term appears in more than 50% of your graph documents ($\mathrm{df} > \frac{N}{2}$):

$$\text{IDF}_{\text{standard}} = \ln \left( \frac{N - df + 0.5}{df + 0.5} \right)$$

Your implementation adds $+1.0$ inside the natural logarithm, which simplifies algebraically to:

$$\text{IDF}_{\text{smoothed}} = \ln \left( \frac{N - df + 0.5}{df + 0.5} + 1 \right) = \ln \left( \frac{N + 1}{df + 0.5} \right)$$   

Because the total number of documents $N$ is always greater than or equal to the document frequency $df$, the numerator $(N + 1)$ is strictly greater than the denominator $(df + 0.5)$ for all valid values ($N \ge df \ge 1$):

$$\frac{N + 1}{df + 0.5} > 1 \implies \ln \left( \frac{N + 1}{df + 0.5} \right) > 0$$   

This guarantees that every query term yields a strictly positive weight, preventing ubiquitous terms like "policy" or "claim" from penalizing node relevance.

## Parameter Configuration Analysis

1. `_K1 = 1.5`: Ideal term-frequency saturation for graph node descriptions. It prevents a node with repeated keywords from dominating short, highly precise node summaries.

2. `_B = 0.75`: Standard Lucene length-normalization. It effectively penalizes overly verbose policy definitions while keeping concise claim summaries competitive.

3. `_ID_BONUS = 5.0`: In standard BM25, raw term relevance scores typically range between $0.5$ and $8.0$. An additive bonus of $+5.0$ guarantees that explicit alphanumeric entity matches (e.g., `CLM-99401` or `POL-33012`) jump straight to Rank 1 while preserving the relative BM25 rank order of all remaining context nodes.
